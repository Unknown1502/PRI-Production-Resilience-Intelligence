## Decisions

**The database password is generated by the script and never printed.** It goes
straight into Secret Manager via `--data-file=-` and is read back with
`gcloud secrets versions access`. Nothing secret ever appears on a command line
or in shell history.

**`pri-consumer` runs at min-instances 1 and everything else scales to zero.**
That is the project's only standing charge, and it is unavoidable: a Kafka
listener with no instance running is not listening, and the disruption that
arrives while it is asleep is exactly the one the system exists to catch. Called
out prominently in `infra/README.md` with the alternative for after judging.

**One uvicorn worker.** The SSE broker is in-process; a second worker in the
same container would give half the connected clients a stream that never fires.

**The web image is built *after* the API is deployed.** `NEXT_PUBLIC_*` is
inlined at build time, so the API URL has to be known before `npm run build`
runs. The script captures the deployed URL and passes it as a build arg.

**Artifacts write to `/app/artifacts`, container-local.** Cloud Run's filesystem
is ephemeral, which is correct here: the artifact table records the path and a
regenerated version rewrites it, so nothing durable lives on disk.

**Non-root in all three images.** A container that can write to its own
site-packages is a container that can be made to run something else.

## How to run it

```bash
export GOOGLE_CLOUD_PROJECT=your-project-id
export GOOGLE_CLOUD_REGION=us-central1
export CONFLUENT_BOOTSTRAP_SERVERS=... CONFLUENT_API_KEY=... CONFLUENT_API_SECRET=...

./infra/deploy.sh
```

Then:

```bash
curl -s "$API_URL/health"
python scripts/run_demo.py --api "$API_URL"
```

## Not covered

**Nothing here has been executed.** No GCP project was available in this
session, so the script is reviewed and internally consistent but unproven. The
first real run will find something — it always does. Most likely candidates: the
Cloud Build inline-config heredoc in step 9, the `^@^` delimiter syntax on the
`DATABASE_URL` env var, and whether the Cloud SQL socket path is right for
asyncpg.

**No image scanning, no Binary Authorization, no VPC connector.** The API and
web services are `--allow-unauthenticated` by design, so a judge needs no
credentials, but that also means the mutating routes are protected only by
`PRI_API_KEY` — which the demo deployment leaves empty.

**No custom domain, no CDN, no uptime check.** The judges test between Sep 23
and Oct 7; an uptime check that emails on failure would be worth more than any
of the rest of this list.
